Zineroo

A local-first browser based React tool for making printable foldable zines, bifold booklets, and trifold brochures from images, with auto-fill, layered photo placement, curved text overlays, undo/redo, booklet preview, imposition layout, and export-ready PDF, PNG, ZIP, and project output

The Idea

Zineroo is a focused publishing tool for turning a small image set into a printable folded object. It keeps the workflow in the browser: drop images in, choose a folded zine, bifold booklet, or trifold brochure format, auto-fill the editor, add photo and text layers, reorder pages or spreads, tune the frame, preview the booklet or sheet, and export the files. The project is deliberately local-first. Images are kept in the browser, autosaved to IndexedDB, and exported by the user as files rather than pushed through an account system.

The interface is built around the physical object. The app has fixed page maps, paper presets, format-aware spread controls, full-sheet imposition views, and export controls for the printable artifact. It is not a general design canvas. Its job is to make the zine-making loop fast enough that layout decisions can stay visual and tactile.

Make the folded sheet the source of truth.

Features

Folded formats

  • Eight-page foldable zine format with front cover, six interior pages, and back cover
  • Bifold booklet format with page counts from 4 to 100 pages in four-page increments
  • Trifold brochure format with outside and inside sheet sides
  • Format switching updates page labels, editor grid, preview views, valid spreads, and export sides
  • Drag-and-drop page assignment from the image tray
  • Auto-Distribute fills the editor from the sorted asset tray
  • Re-Order mode moves or swaps single pages, two-page spreads, and valid trifold spread groups
  • Undo and redo controls cover layout edits, placement changes, text edits, imports, and reordering

Image placement

  • Fill and fit modes for fast page framing
  • Freeform mode for manual pan, zoom, and rotation
  • Layered photo placement supports a background image plus additional foreground photo layers
  • Rotation-aware freeform crop constraints and snap guides keep images inside the printable frame
  • Per-page margin and image stroke controls with apply-to-all actions
  • Image overlay colors can tint the whole page or only the placed photo
  • Freeform and aligned crop states are preserved when switching modes

Text and color layers

  • Non-destructive text overlays stored with each page or spread
  • Fullscreen text editor with direct dragging over the image
  • Font, color, highlight, size, tracking, line-height, padding, alignment, rotation, and curve controls
  • Self-hosted display, serif, mono, script, and typewriter font options
  • Text overlays render through the same canvas path as previews, PDF, and PNG output

Preview and export

  • Editor view for the active format's complete page set
  • Booklet and brochure preview modes with format-specific navigation
  • Full-sheet imposition preview using the print order required for folding or double-sided trifold printing
  • Standard 144 PPI PDF export via jsPDF for sharing and simple printing
  • Print shop PDF export at 300 PPI with optional bleed, crop marks, and local CMYK conversion through uploaded ICC or ICM profiles
  • Single-sheet PNG export and zipped multi-sheet PDF or PNG export for booklet and brochure output
  • Optional ZIP export bundles the rendered PDF or PNG files with a portable project JSON archive
  • Print guidance explains direct printing, PDF printing, and print-shop export paths before download
  • Download-complete dialog shows zine folding instructions, trifold settings, or print-shop PDF notes
  • Lightweight preview images keep editing responsive while exports render from original uploads

Local persistence

  • Autosaves the working project to IndexedDB with visible save status
  • Restores the saved project on reload
  • Stores original image blobs locally and regenerates runtime preview URLs when restored
  • New Zine confirms before clearing local autosave and returning to a blank project
  • Object URLs and image caches are cleaned up on reset, removal, and import
  • Desktop beta gate protects the current editor from unsupported mobile and short viewport layouts

The data model is intentionally small. A project is a title, a format, a local asset library, page slots, and design settings. Page slots own their background image placement, additional photo layers, overlay color, text layers, and spread metadata. Runtime object URLs are stripped before autosave and project export, then rebuilt when the project is restored. Uploaded originals stay available for export while generated preview blobs keep the editor responsive.

Layer model

The original single-photo page slot now behaves as the background layer, while foreground photo layers use the same crop, fit, freeform, stroke, margin, and overlay controls. That lets the editor add richer collage-style pages without forking the rendering path. Canvas preview, full-sheet export, print PDF output, and project save/load all consume the normalized layer model.

Preview asset pipeline

const PREVIEW_MAX_LONG_EDGE = 1200;

function imageForAsset(asset: RuntimeAsset, source: 'preview' | 'original' = 'preview') {
  const url = source === 'preview' ? asset.previewUrl ?? asset.url : asset.url;
  return loadImageFromUrl(url, `Could not load ${asset.name}`);
}

The editor renders from preview-sized blobs when possible, but PDF and PNG export request the original image source. That keeps drag, crop, and preview interactions light without lowering print output quality.

Format-aware sheets

const IMPOSITION_PAGES = [7, 6, 5, 4, 8, 1, 2, 3];
const TRIFOLD_OUTSIDE_PAGES = [2, 6, 1];
const TRIFOLD_INSIDE_PAGES = [3, 4, 5];

The full-sheet preview and PDF export use the same format definitions, so the visual preview matches the file that is saved. Foldable zines render one imposed sheet with the top row rotated for folding. Trifolds render separate outside and inside sides for double-sided printing. Bifold booklets render the required imposed sheet sequence so longer booklets can be exported as a set of printable PDF sheets.

Reorder model

type ReorderDropPosition = 'before' | 'after' | 'on';
type ReorderUnit = {
  kind: 'single' | 'spread';
  length: 1 | 2 | 3;
  startIndex: number;
};

Reordering treats a spread as one unit, whether it spans two pages or a full three-panel trifold side. Boundary drops move content before or after another slot, while direct drops swap compatible blocks. Spread metadata is normalized after each move so paired and grouped pages stay together.

History model

The editor keeps an undo/redo stack around complete project snapshots, with grouping for continuous text and control edits so sliders and typing do not flood history. The text editor has its own temporary draft history while open, then commits the finished overlay state back into the project history when the modal closes.

Export flow

async function renderPdfBlob() {
  const paper = sheetSize(project.settings);
  const pdf = new jsPDF({
    orientation: 'landscape',
    unit: 'pt',
    format: [paper.width, paper.height],
  });

  for (const [index, side] of sheetSidesForFormat(projectFormat(project)).entries()) {
    if (index > 0) pdf.addPage([paper.width, paper.height], 'landscape');
    const sheet = await renderImpositionCanvas(project, Math.round(paper.width * 2), {
      showGuides: false,
      imageSource: 'original',
      sideId: side.id,
    });
    pdf.addImage(sheet.toDataURL('image/jpeg', 0.95), 'JPEG', 0, 0, paper.width, paper.height);
  }

  return pdf.output('blob');
}

Export is canvas-first. The app renders the printable side or sides, then routes that same rendering to PDF, PNG, or ZIP. Standard PDFs prioritize quick sharing and home printing. Print shop PDFs render at 300 PPI, can add bleed and crop marks, and can flatten through a local CMYK conversion path when the user supplies a printer profile. Project export is separate but can be bundled with the rendered artifact: it serializes the project state and embeds original image blobs as data URLs so the work can be moved between browsers without carrying runtime preview blobs or object URLs.

Design Notes

The UI uses a print-shop vocabulary: heavy rules, square controls, hard shadows, paper tones, and a narrow red accent. The panels map to the workflow: image tray on the left, working sheet in the center, design controls on the right. The app favors visible mechanics over hidden menus because the user is making a physical object and needs to see the consequences of each change immediately.

The most important view is the full sheet. Individual pages matter, but the final object is the folded imposition. Keeping that view one click away makes mistakes visible before the user prints. A beta desktop gate is also part of that design decision: until the mobile editor is ready, the app explicitly asks people on small screens to continue on a computer instead of offering a cramped, unreliable canvas.
