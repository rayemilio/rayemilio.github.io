Zine Maker

A local-first browser based React tool for making printable eight-page zines from images, with auto-fill, page and spread reordering, booklet preview, imposition layout, and export-ready PDF output

The Idea

Zine Maker is a focused publishing tool for turning a small image set into a printable folded zine. It keeps the workflow in the browser: drop images in, auto-fill the editor, reorder pages or spreads, tune the frame, preview the booklet, and export the sheet. The project is deliberately local-first. Images are kept in the browser, autosaved to IndexedDB, and exported by the user as files rather than pushed through an account system.

The interface is built around the physical object. The app has eight fixed pages, paper presets, a full-sheet imposition view, and export controls for the printable artifact. It is not a general design canvas. Its job is to make the zine-making loop fast enough that layout decisions can stay visual and tactile.

Make the folded sheet the source of truth.

Features

Eight-page zine structure

  • Fixed eight-page project model with front cover, six interior pages, and back cover
  • Drag-and-drop page assignment from the image tray
  • Auto-Distribute fills the editor from the sorted asset tray
  • Re-Order mode moves or swaps single pages and valid spreads
  • Spread pairing for valid interior page pairs, with reordering that preserves the pair

Image placement

  • Fill and fit modes for fast page framing
  • Freeform mode for manual pan, zoom, and rotation
  • Per-page margin and image stroke controls with apply-to-all actions
  • Crop constraints keep aligned placements inside the printable frame
  • Freeform and aligned crop states are preserved when switching modes

Preview and export

  • Editor view for all eight pages
  • Booklet preview with front, spread, and back navigation
  • Full-sheet imposition preview using the print order required for folding
  • PDF export via jsPDF, PNG sheet export, and portable project JSON export/import
  • Lightweight preview images keep editing responsive while exports render from original uploads

Local persistence

  • Autosaves the working project to IndexedDB with visible save status
  • Restores the saved project on reload
  • Stores original image blobs locally and regenerates runtime preview URLs when restored
  • New Zine confirms before clearing local autosave and returning to a blank project
  • Object URLs and image caches are cleaned up on reset, removal, and import

Architecture

Source structure

Core project model

type ZineProject = {
  version?: number;
  title: string;
  assets: ZineAsset[];
  pages: PageSlot[];
  settings: DesignSettings;
};

type ZineAsset = {
  id: string;
  name: string;
  type: string;
  blob: Blob;
  width: number;
  height: number;
  previewBlob?: Blob;
  previewWidth?: number;
  previewHeight?: number;
};

type PageSlot = {
  id: number;
  assetId?: string;
  fit: 'cover' | 'contain' | 'spread';
  crop: { x: number; y: number; zoom: number; rotation: number };
  freeformCrop?: { x: number; y: number; zoom: number; rotation: number };
  freeform: boolean;
  margin: number;
  imageBorder?: number;
  imageStroke?: string;
  spreadId?: string;
  spreadSide?: 'left' | 'right';
};

The data model is intentionally small. A project is a title, a local asset library, eight page slots, and design settings. Runtime object URLs are stripped before autosave and project export, then rebuilt when the project is restored. Uploaded originals stay available for export while generated preview blobs keep the editor responsive.

Preview asset pipeline

const PREVIEW_MAX_LONG_EDGE = 1200;

function imageForAsset(asset: RuntimeAsset, source: 'preview' | 'original' = 'preview') {
  const url = source === 'preview' ? asset.previewUrl ?? asset.url : asset.url;
  return loadImageFromUrl(url, `Could not load ${asset.name}`);
}

The editor renders from preview-sized blobs when possible, but PDF and PNG export request the original image source. That keeps drag, crop, and preview interactions light without lowering print output quality.

Imposition order

const IMPOSITION_PAGES = [7, 6, 5, 4, 8, 1, 2, 3];

The full-sheet preview and PDF export use the same imposition order, so the visual preview matches the file that is saved. Top-row pages are rotated during canvas drawing to match the physical fold.

Reorder model

type ReorderDropPosition = 'before' | 'after' | 'on';
type ReorderUnit = {
  kind: 'single' | 'spread';
  length: 1 | 2;
  startIndex: number;
};

Reordering treats a spread as a two-page unit. Boundary drops move content before or after another slot, while direct drops swap compatible blocks. Spread metadata is normalized after each move so paired pages stay together.

Export flow

async function exportPdf() {
  const paper = sheetSize(project.settings);
  const pdf = new jsPDF({
    orientation: 'landscape',
    unit: 'pt',
    format: [paper.width, paper.height],
  });
  const sheet = await renderImpositionCanvas(project, Math.round(paper.width * 2), {
    showGuides: false,
    imageSource: 'original',
  });
  const image = sheet.toDataURL('image/jpeg', 0.95);
  pdf.addImage(image, 'JPEG', 0, 0, paper.width, paper.height);
  pdf.save(`${project.title || 'zine'}.pdf`);
}

Export is canvas-first. The app renders the printable sheet once, then routes that same rendering to PDF or PNG. Project export is separate: it serializes the project state and embeds image blobs as data URLs so the work can be moved between browsers without carrying runtime preview blobs or object URLs.

Design Notes

The UI uses a print-shop vocabulary: heavy rules, square controls, hard shadows, paper tones, and a narrow red accent. The panels map to the workflow: image tray on the left, working sheet in the center, design controls on the right. The app favors visible mechanics over hidden menus because the user is making a physical object and needs to see the consequences of each change immediately.

The most important view is the full sheet. Individual pages matter, but the final object is the folded imposition. Keeping that view one click away makes mistakes visible before the user prints.
